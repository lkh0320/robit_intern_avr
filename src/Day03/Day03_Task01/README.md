# 임베디드 통신 방식 조사 보고서

# 1. I2C 통신

## 1.1 I2C 통신이란?

I2C(Inter-Integrated Circuit)는 마이크로컨트롤러와 여러 주변 장치 사이에서 데이터를 주고받기 위해 사용되는 직렬 통신 방식이다.

주로 센서, LCD, EEPROM, RTC(Real Time Clock)와 같은 다양한 부품을 연결할 때 사용된다.

I2C의 가장 큰 특징은 **두 개의 통신선만 사용하여 여러 개의 장치를 연결할 수 있다는 점**이다.

일반적인 병렬 통신은 데이터를 전달하기 위해 여러 개의 선이 필요하지만, I2C는 데이터선과 클럭선만 사용하기 때문에 회로 구성이 간단하고 배선 수를 줄일 수 있다.


---

# 1.2 I2C 통신 구조

I2C 통신은 크게 두 개의 신호선으로 구성된다.


| 신호 | 이름 | 역할 |
|---|---|---|
| SCL | Serial Clock Line | 데이터 전송 시간을 맞추기 위한 클럭 신호 |
| SDA | Serial Data Line | 실제 데이터가 이동하는 신호선 |


## SCL (Serial Clock Line)

SCL은 데이터 전송 타이밍을 맞추기 위한 클럭 신호이다.

I2C에서는 Master 장치가 SCL 신호를 직접 생성한다.

데이터를 주고받을 때 SCL의 변화 시점을 기준으로 SDA의 데이터를 읽는다.


## SDA (Serial Data Line)

SDA는 실제 데이터가 전달되는 선이다.

주소 정보와 실제 데이터가 모두 SDA를 통해 전달된다.

또한 I2C는 양방향 통신 방식이기 때문에 하나의 SDA 선으로 데이터 송신과 수신이 가능하다.


---

# 1.3 I2C 통신 원리

I2C는 Master와 Slave 구조로 동작한다.


## Master

통신을 시작하고 전체 통신 과정을 제어하는 장치이다.

예:

- ATmega128
- Arduino
- Raspberry Pi


Master는 SCL 클럭을 생성하고 Slave의 주소를 이용하여 원하는 장치를 선택한다.


## Slave

Master의 요청을 받아 데이터를 전달하는 장치이다.

각 Slave 장치는 고유한 주소(Address)를 가지고 있으며 Master는 이 주소를 이용해 특정 장치와 통신한다.

예:

- 온도 센서
- LCD
- EEPROM
- RTC 모듈


---

# 1.4 I2C 데이터 전송 과정


## 1) Start Condition

Master가 통신 시작을 알리는 신호를 발생시킨다.

SCL이 HIGH인 상태에서 SDA가 HIGH에서 LOW로 변하면 Start Condition이 된다.


## 2) Slave Address 전송

Master는 통신할 Slave의 주소를 SDA를 통해 전송한다.

주소의 마지막 비트는 데이터 방향을 결정한다.


| 비트 값 | 동작 |
|---|---|
| 0 | Write (Master → Slave) |
| 1 | Read (Slave → Master) |


## 3) 데이터 전송

주소가 일치하는 Slave가 응답하면 실제 데이터 전송이 시작된다.

데이터는 8비트 단위로 전송되며 전송 후에는 ACK 신호를 통해 정상 수신 여부를 확인한다.


## 4) Stop Condition

Master가 통신 종료를 알리는 신호를 발생시킨다.

SDA가 LOW에서 HIGH로 변경되면서 통신이 종료된다.


---

# 2. ATmega128에서의 I2C 사용법

ATmega128에서는 I2C 기능을 TWI(Two Wire Interface)라는 이름으로 제공한다.

TWI는 I2C와 동일한 방식으로 동작하며 두 개의 선(SDA, SCL)을 이용하여 통신한다.


# 2.1 ATmega128 I2C 핀


| 기능 | ATmega128 핀 |
|---|---|
| SDA | PC1 |
| SCL | PC0 |


해당 핀은 TWI 전용 기능으로 사용할 수 있다.


---

# 2.2 ATmega128 I2C 주요 레지스터


## TWBR (TWI Bit Rate Register)

I2C 통신 속도를 결정하는 레지스터이다.

SCL 주파수는 다음 식으로 계산된다.


```
SCL Frequency =
F_CPU / (16 + 2 × TWBR × Prescaler)
```


일반적으로 센서 통신에서는 100kHz 또는 400kHz 속도를 많이 사용한다.


---

## TWSR (TWI Status Register)

현재 I2C 통신 상태를 확인하는 레지스터이다.

예:

- Start Condition 완료
- Slave 주소 전송 완료
- 데이터 전송 완료

등의 상태를 확인할 수 있다.


---

## TWCR (TWI Control Register)

TWI 동작을 제어하는 레지스터이다.

주요 비트:


| 비트 | 기능 |
|---|---|
| TWINT | 통신 완료 표시 |
| TWSTA | Start 신호 생성 |
| TWSTO | Stop 신호 생성 |
| TWEN | TWI 활성화 |


---

## TWDR (TWI Data Register)

실제로 전송하거나 수신하는 데이터를 저장하는 레지스터이다.


---

# 2.3 ATmega128 I2C 초기화 예시


```c
void I2C_Init(void)
{
    TWBR = 72;
    TWSR = 0x00;
    TWCR = (1 << TWEN);
}
```


동작 과정:

1. TWBR을 이용하여 통신 속도 설정
2. Prescaler 설정
3. TWEN 비트를 활성화하여 TWI 기능 사용


---

# 2.4 I2C 장점과 단점


## 장점

- 두 개의 선만으로 여러 장치 연결 가능
- 배선이 간단함
- 주소 방식으로 여러 Slave 사용 가능
- 센서나 LCD 같은 저속 장치 연결에 적합


## 단점

- UART나 SPI보다 속도가 느림
- 긴 거리 통신에는 적합하지 않음
- 여러 장치 사용 시 주소 충돌 가능


---

# 3. UART 통신


# 3.1 UART란?


UART(Universal Asynchronous Receiver Transmitter)는 비동기 방식의 직렬 통신 방식이다.

클럭선을 사용하지 않고 송신 장치와 수신 장치가 동일한 Baud Rate를 사용하여 데이터를 주고받는다.


대표적인 사용 예:

- MCU와 PC 통신
- Bluetooth 모듈
- GPS 모듈
- WiFi 모듈


---

# 3.2 UART 통신 구조


UART는 기본적으로 두 개의 선을 사용한다.


| 신호 | 역할 |
|---|---|
| TX | 데이터 송신 |
| RX | 데이터 수신 |


연결 방법:

```
MCU TX  --------  RX PC

MCU RX  --------  TX PC
```


---

# 3.3 UART 데이터 구조


UART 데이터는 다음과 같은 프레임 형태로 전송된다.


```
Start Bit
     ↓
Data Bit (8bit)
     ↓
Parity Bit (선택)
     ↓
Stop Bit
```


Start Bit는 데이터 시작을 알리고,
Stop Bit는 데이터 종료를 의미한다.


---

# 4. RS-232 통신


# 4.1 RS-232란?


RS-232는 UART 데이터를 실제 케이블을 통해 전달하기 위한 물리적 통신 규격이다.

UART는 데이터 형식을 정의하고,
RS-232는 전압 레벨과 연결 방식을 정의한다.


---

# 4.2 RS-232 특징


RS-232는 단일 종단 방식(single-ended)을 사용한다.

즉, 하나의 신호선을 기준으로 전압을 판단한다.


전압 기준:


| 상태 | 전압 |
|---|---|
| Logic 1 | -3V ~ -15V |
| Logic 0 | +3V ~ +15V |


MCU는 보통 5V 또는 3.3V 신호를 사용하기 때문에 MAX232 같은 전압 변환 IC가 필요하다.


---

# 4.3 RS-232 장점


- 구조가 간단함
- PC와 연결이 쉬움
- 오래 사용되어 호환성이 높음


# 4.4 RS-232 단점


- 통신 거리가 짧음
- 노이즈에 약함
- 여러 장치 연결이 어려움


---

# 5. RS-485 통신


# 5.1 RS-485란?


RS-485는 산업 환경에서 많이 사용하는 장거리 직렬 통신 방식이다.

RS-232와 달리 차동 신호 방식을 사용하기 때문에 외부 노이즈에 강하다.


---

# 5.2 RS-485 특징


RS-485는 두 개의 신호선을 사용한다.


| 신호 | 역할 |
|---|---|
| A | 차동 신호 |
| B | 반대 방향 신호 |


두 신호의 전압 차이를 이용하여 데이터를 판단한다.


---

# 5.3 RS-485 장점


- 긴 거리 통신 가능
- 노이즈에 강함
- 여러 장치 연결 가능
- 산업 자동화 시스템에 적합


# 5.4 RS-485 단점


- 회로 구성이 복잡함
- 별도의 변환 IC 필요
- 통신 제어 방식이 조금 더 복잡함


---

# 6. RS-232와 RS-485 비교


| 항목 | RS-232 | RS-485 |
|---|---|---|
| 신호 방식 | 단일 종단 방식 | 차동 방식 |
| 통신 거리 | 짧음 | 김 |
| 노이즈 내성 | 약함 | 강함 |
| 연결 방식 | 1:1 | 1:N |
| 사용 분야 | PC 주변기기 | 산업 장비 |
| 회로 구성 | 간단 | 복잡 |


---

# 7. 결론


I2C는 SCL과 SDA 두 개의 선을 이용하여 여러 장치를 연결할 수 있는 통신 방식으로, 센서나 LCD 같은 주변 장치 연결에 적합하다.

ATmega128에서는 TWI 기능을 이용하여 I2C 통신을 구현하며 TWBR, TWSR, TWCR, TWDR 등의 레지스터를 사용하여 통신 속도와 동작을 제어한다.


UART는 가장 기본적인 직렬 통신 방식이며, 이를 기반으로 RS-232와 RS-485 같은 실제 통신 규격이 만들어졌다.

RS-232는 가까운 거리에서 간단한 장치를 연결할 때 적합하고, RS-485는 긴 거리와 노이즈가 많은 산업 환경에서 사용하기 적합하다.
